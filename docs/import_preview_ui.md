# 导入外部账单预览 UI 定稿

- 状态：用户已确认十条设计结论、三点微调、搜索定案及人工验收后的箭头／样式／操作引导修订；本文件为阶段 4 实现与验收的唯一 UI 依据。
- 产品依据：方案草稿 Q1、Q2、Q4、Q5、Q6、§5.1、§5.2、§7.1，以及用户后续裁决；本文件收敛界面行为，不增加平台模板、账目规则或对账入口。
- 先前两张图片仅为布局与风格参考；卡片入口、组级确认、退款对操作位置、计数措辞、默认排序及搜索，以本文为准。
- 范围：单文件、单明细区的导入预览及映射保存；不包括批次列表、导入报告页，不提供逐笔修改日期、金额或备注的编辑功能。
- 保持既定产品边界：不识别平台来源，不存外部单号，不自动打标签或把交易对方写入 tags.json；本次 UI 定稿不解除真实样例逐行对账的后续门禁。

## 一、四区布局与元素

- 窗口标题为「导入外部账单」，顶部显示文件名；布局为上方四类计数卡片、中部左侧字段映射和右侧明细、下方固定操作栏。
- 延续现有界面：背景 #F0F4F8，白色面板、约 14 像素圆角；按钮及下拉约 8 像素圆角；主色 #2F80ED，正文 #243447，辅助文字 #64748B，边框 #D8E1EA；字体 Microsoft YaHei UI。
- 黄色用于待处理及待改提示，绿色用于已确认反馈；禁用按钮用灰色。颜色必须同时配文字或图标，不仅靠颜色区分状态。
- 窗口可调整大小；字段区和明细区内容分别可访问，底部取消与提交入口始终可见，不能因展开内容被挤出窗口。
- 所有数量文案统一用「笔」，如「待确认 8 笔」「共 116 笔」「已处理 86 笔」；原始位置仍写「原始第 41 行」。退款对可另标「1 对」，两笔分别计数。
- 顶部常驻「核对字段对应 → 处理待确认记录 → 确认导入」指引，不拆分成新页面。按当前状态提示下一步；有待确认记录时显示数量及「去处理」，点击切换待确认视图。
- 所有下拉使用同一浅底细边框选择框，仅右侧一个实心三角：收起 ▼、展开 ▲，文字不再夹带箭头。整框可点击；选项使用白底圆角弹层、浅蓝悬停／键盘定位、当前值勾标，长列表滚动；方向键移动、回车选择、Esc 或点击外部关闭，不使用灰色原生菜单。
- 普通选择框及辅助按钮使用浅色，蓝色主要用于确认操作；卡片以蓝色边框和勾标突出当前视图。表格表头、选中行风格与主页面一致，不影响其他窗口主题。

### 1. 字段映射区

- 每个字段显示中文角色、最终匹配列及修正下拉；列按「列名 · 第 N 列」标识，同名列依靠列位置区分。
- 日期、金额标必需；收支方向、状态、交易类型、主单号直接展示；副单号、消费分类置于可展开的「更多字段」。可选角色可选「不使用」。
- 所有自动映射均可修正；不确定或必需字段缺失时高亮对应控件。只展示最终映射，不展示评分、内部高／中／低档、置信度或算法候选列表。
- 「备注来源」提供交易对方、商品/说明、原备注、支付方式的列绑定与启用勾选；前三项默认启用，支付方式默认关闭；「保留时间到备注 [HH:MM]」默认关闭。
- 备注最终顺序固定为时间前缀、[退款]、交易对方、商品/说明、原备注、支付方式；空格分隔、空值跳过。[退款] 仅用于明确入账的退款；时间缺失或异常不添加前缀。
- 常驻提示「修改字段映射将重置待确认决定」；字段下拉修改立即重算，不弹确认框，不能等到确认导入才刷新。
- 右上为「已保存映射」，右下为「保存此映射」。保存映射候选属于用户保存内容，与禁止展示的算法候选是两回事。
- 整个文件未使用状态列时显示「本次未识别到状态列」；有状态列但某笔为空、无法读取或未命中时仍为待确认，不以无状态列提示掩盖。
- 区标题为「账单字段对应」，附说明「选择文件中的哪一列作为记账字段」。每个已绑定字段显示一条来源样例，完整原值仍可在明细核对；样例仅帮助理解，不改变映射或规则。必需字段留空时显示「请选择日期列／请选择金额列」，可选字段才显示「不使用」。
- 「保存此映射，下次复用」作为辅助入口；无可用保存项时提示可以直接核对下方字段，不要求先保存才能继续。

### 2. 四类计数区

- 四张卡片依次为「将导入」「规则跳过」「待确认」「非交易行」，各显示数量与统一入口「展开」。点击卡片任意可点击区域或入口，均切换右侧对应视图；重复点击当前卡片保持该视图。
- 当前卡片以边框／底色及选中标识区分；共用右侧明细区，不叠加第二张表。切换只更新视图，不重新读取文件、不重算规则、不清除已生效决定。
- 初次展示有待确认记录时默认进入待确认处理视图，否则进入将导入视图；之后处理记录不自动抢占用户选择的视图。
- 卡片统计整个当前预览的最终类别，每笔只计一个类别；搜索、仅看未处理、前 5 笔摘要及滚动位置均不改变卡片数字。
- 将导入包含自动判定可入账及用户明确入账；规则跳过包含中性、失败关闭、重复及用户跳过；非交易行单独统计，不并入跳过笔数。
- 待确认卡片只统计当前尚未决定的笔数；待确认处理视图还可回看本轮已处理记录，这些记录的最终类别仍属于将导入或规则跳过，不能重复计数。

### 3. 明细区

- 表头包含「原始行」「本地日期」「带符号金额」「备注」「处理结果」，金额明确保留正负号；缺失值显示「—」，不能用 0 或虚构日期填充。
- 点击记录可核对关键原值和原因；长备注及状态值可完整查看，不能仅靠截断文本判断。表格内容只读，处理按钮改变决定而非编辑原始数据。
- 各视图顶部提供文本框「搜索行号、日期、金额、备注或处理结果」和清空入口；显示当前视图及匹配笔数，搜索不替换四类计数。
- 将导入视图展示最终待写入的日期、带符号金额、备注及处理结果；其中的待确认来源记录仍可在待确认处理视图回看并修改决定。
- 规则跳过、非交易行可先展示前 5 笔，超出显示「共 X 笔，当前展示前 5 笔」及「查看全部」；每笔可核对原始行号、关键原值与原因。
- 规则跳过视图将「用户选择跳过」单独作为子分类，行旁加「用户选择」小标，区别于系统规则跳过；此处按最终类别正常展示，不加「已处理」标记。
- 规则跳过中的完全重复提供「仍要导入」勾选；它只解除重复跳过，随后按语义重新归类。退款、未知状态或字段异常仍须处理，不能直接绕过校验入账。
- 无主单号的五字段疑似重复保留默认导入并提示核对；同单号有差异仅提示。提示不新增第五类别，不改变已有退款／未知等语义结果。
- 待确认视图按主要原因分组，全部记录可通过滚动访问，不受前 5 笔限制；提供默认勾选的「仅看未处理」及「定位下一笔未处理」。
- 「规则冲突」标题旁小字说明「字段或判断有冲突，请核对原因」；「疑似退款对」说明「相似记录金额相反，请核对两笔」。详细原值与具体阻断原因仍在记录处显示。
- 点击记录后，核对区明确标「正在处理：原始第 X 行」；最终试算以「入账后内容／处理后内容」列出日期、金额、备注，另以「原始内容（只读）」区分来源值。金额旁说明收入为正、支出为负，不把拼接文本当作未说明用途的调试输出。
- 行操作命名为「此笔入账」「跳过此笔」，只作用于选中记录；未选中、正在试算、字段阻断、退款对需成对处理等情况，在按钮旁显示具体原因。退款对成员不提供独立决定，继续使用对标题处操作。

### 4. 底部操作区

- 左侧显示阻断原因或当前可导入数量，并提示「预览尚未写入账本」；右侧为「取消」及「确认导入（X 笔）」；X 为全部最终将导入笔数，不是搜索匹配笔数。
- 缺少必需映射、仍有待确认记录、正在重算或重算失败时禁用确认导入，并说明原因。金额为零、超过两位小数或方向未解决的记录禁止入账，允许明确跳过。
- 仅选择了组级下拉或退款对默认选项，不代表已处理；确认按钮不得据此提前启用。
- 确认导入只提交全部最终将导入记录，不只提交当前卡片或搜索结果；预览期间任何选择都未写入账本。
- 取消或关闭预览不写账本；用户此前显式保存的映射不因取消预览被撤销。

## 二、待确认决定与三个视觉状态

- 普通组统一采用「选择处理方式」下拉、「确认处理本组」按钮和「清除本组决定」；只选择下拉不生效，必须明确确认。规则冲突组也使用同样结构，不保留草图中即时生效的「本组跳过」特例；三角由控件独立绘制。
- 可选动作遵守必要字段校验。组内有不能入账的记录时，不提供能绕过校验的整组入账；显示原因，仍可整组跳过或对可入账记录逐笔处理。
- 未选择：下拉显示「选择处理方式」，尚无待生效选择；普通组的确认按钮禁用，旁标「请先选择处理方式」，不显示已确认勾标。
- 已选择未确认：显示所选动作，自动准备最终处理预览；试算期间提示「正在生成结果预览」，成功后确认按钮高亮，旁标「尚未生效，请确认」；行结果、分类计数及已处理数量保持原值。
- 已确认：确认后显示勾标与「已确认」反馈，确认按钮不保持待生效高亮，行结果同步为「已确认入账」或「已确认跳过」；再次改选回到待确认选择状态，原已生效结果保持到下一次明确确认。
- 三态描述的是选择与确认，不是内部识别档位；字段映射下拉仍按即时重算执行，不能套用组级的延后生效行为。
- 逐笔的「此笔入账」「跳过此笔」按钮本身是明确决定，点击即生效；已处理行保留原位置，以勾标、处理结果及弱化背景区分，日期、金额与备注仍清晰可读，不移到列表底部。
- 同一笔用户选择跳过的记录，在待确认处理视图的回看区带「已处理」标记及弱化背景，在规则跳过视图按正常记录展示；两处使用同一原始行号，是处理历史与最终类别的不同呈现，不是两笔记录。
- 处理一笔后立即显示结果；开启「仅看未处理」时该笔退出当前可见列表，焦点转到下一笔可见的未处理记录；关闭此筛选即可回看并修改已作出的决定。
- 修改已确认决定时，以当前行实际结果为准；逐笔调整使整组结果不再统一时，本组下拉恢复「选择处理方式」，不撤销行决定；原组级选择不能掩盖不同结果，也不能把重新选择但尚未确认的动作当成生效。
- 本组确认作用于本轮该原因组的完整记录，不受搜索或仅看未处理影响；入口明确标「批量处理本组（X 笔）：包含已处理及筛选隐藏的记录」，避免误认为只作用于可见行。组操作集中在组标题区，与底部的单笔处理分开。
- 「清除本组决定」覆盖本组全部相关记录，包括已处理及被筛选隐藏者，同时清除待生效组选择；重新按当前语义显示待确认，其他组决定不受影响。

### 退款与退款对

- 退款入账动作旁先展示最终日期、正金额及带 [退款] 的备注；用户明确选择后才入账，不将原交易金额推断为另一个退款额；金额含义未明确时不能据此强行入账。
- 疑似退款对的组标题右侧保留组级操作；仅一对时，对级下拉及「确认本对」放在该标题右侧，避免与两笔明细中的行级按钮混排。
- 多对时，每对有独立标题，标出两笔原始行号；下拉及「确认本对」放在对应对标题右侧，不能用一个未标明范围的按钮决定任意一对。组级操作覆盖整组时明确标「确认处理本组」。
- 唯一、无歧义的对提供「两笔都跳过」「只记支出」「两笔都记」「只记退款」；默认显示两笔都跳过，同时提示「默认选项未确认，两笔仍待确认」。默认选项可明确确认，但不自动生效。
- 首个可见退款对默认自动准备两笔核对内容，不要求先点击其中一行。其他尚未准备核对内容的对显示「核对本对」，点后展示完整结果并切为「确认本对」；核对与默认试算都不作出决定。改选动作同样自动准备预览，失败说明原因。
- 用户改选后呈现待确认选择状态；确认处完整展示两笔最终日期、金额及备注，确认本对同时决定两笔，配对明细不提供相互独立的入账按钮。
- 配对不明确时显示原因，不提供四种组合，也不任意配对或推断退款额；保留跳过及调整映射的路径。包含歧义记录的组不得用批量组合绕过歧义。
- 清除疑似退款对组决定时，清除每对内两笔及其他相关记录的决定；每对按对操作，四类计数和处理进度均按笔统计。

## 三、处理进度与实时更新

- 「本轮」从本次字段映射重算完成开始；本轮总量是本轮需要人工确认的记录总笔数，包含之后已由用户处理的记录，不包含系统自动入账、自动跳过及非交易行。
- 已处理量是本轮已有用户明确入账或跳过决定的笔数；不是系统自动判定数量。剩余量是本轮尚无明确决定的笔数，与当前待确认卡片相同。
- 本轮总量不因处理减少；清除决定使已处理量减少、剩余量增加；修改已处理记录的入账／跳过选择不重复增加已处理量。
- 解除重复跳过后新增需要人工确认的记录时，将其纳入本轮总量；字段映射重算则重新统计本轮，不沿用旧进度。
- 本轮总量超过 50 笔时顶部显示「本轮总量 X 笔 · 已处理 Y 笔 · 剩余 Z 笔」；进度不受搜索影响，即使处理后只剩 8 笔，仍展示整轮进度。
- 草图的 94／86／8 表示：本轮 94 笔曾需人工确认，其中用户明确决定 86 笔，剩余 8 笔；例中 86 笔均选择入账，另有系统跳过 16 笔和非交易行 6 笔，合计 116 笔。
- 例中「将导入 86 笔」碰巧等于「已处理 86 笔」；一般情况下两者不相等，因为将导入还可包含自动入账，而已处理还可包含用户跳过。
- 确认入账一笔：待确认 8→7、将导入 86→87、底部导入笔数 86→87，已处理增加一笔；确认跳过一笔则待确认减少、规则跳过增加、导入笔数不变。
- 一对明确处理时，剩余量减少两笔，分别按组合计入将导入或规则跳过；清除决定按相反方向同步更新。仅改选未确认时上述数字均不变化。
- 所有决定生效后立即更新相关行、卡片、进度和提交状态，不需要重新导入或重新读取文件；最后一笔解决后，还须满足必需字段和重算状态守卫才能启用提交。

## 四、各视图固定默认排序

- 将导入：本地日期升序，同日按原始行号升序。
- 规则跳过：按中性交易／不计收支、失败／关闭、重复、用户选择跳过的顺序分组，组内按原始行号升序。
- 待确认处理：按规则冲突、疑似退款对、已识别退款、未知状态的顺序分组；普通组按原始行号升序，退款对按较小原始行号排列，对内按原始行号排列并保持关联。
- 非交易行：按原始行号升序，便于与文件逐行核对。
- 已处理记录在待确认处理视图中保留所属组及排序位置；搜索结果沿用所属视图排序。v1 不提供点击表头或其他入口切换排序。

## 五、搜索与明细切换

- 搜索是简单文本过滤，作用于当前视图的完整记录集合，不只作用于已渲染行或前 5 笔摘要；不修改原始数据、决定、映射、分类及全局计数。
- 单个查询按文本包含匹配原始行号、本地日期、显示金额、备注、处理结果任一项；不提供多关键词运算、正则或高级过滤。
- 原始行号按数字文本匹配，日期按界面日期文本匹配，金额按带符号显示文本匹配；输入前后空白忽略，纯空白等同清空。查询文本不按空值词表清洗。
- 搜索实时更新可见结果；当前视图无命中时显示「未找到匹配记录」，卡片数量和底部导入数量仍显示完整预览数量。
- 清空后恢复当前视图的完整搜索前集合，保留「仅看未处理」等既有视图筛选；若规则跳过／非交易行仍处于前 5 笔摘要，恢复该摘要及查看全部入口，而非遗漏后续记录。
- 搜索期间按匹配结果浏览完整集合，不沿用前 5 笔截断；清空或切换卡片不改变处理决定。
- 切换卡片时替换明细内容、标题及默认排序，保留搜索文本并在新视图应用；滚动回顶部，不残留上一视图选中行或原值详情。
- 「仅看未处理」仅属于待确认处理视图；决定生效或处理结果被修改后重新应用当前文本过滤，可能使记录退出或进入可见结果，进度仍统计整轮。
- 「定位下一笔未处理」按当前视图顺序定位符合现有筛选的下一笔，到达末尾后回到第一笔，形成环形；按钮不因到达末尾而禁用。无可见未处理记录时提示「当前筛选无未处理记录」，不能静默清空搜索或把全局剩余量改成 0。
- 搜索仅影响明细可见性，不能拆开对级决定；即使一对只有一笔命中，确认处也须完整呈现两笔日期、金额、备注及覆盖两笔的范围，不得只看命中一笔就决定整对。

## 六、保存与套用映射

- 点击「保存此映射」弹出命名框，预填「月日 时:分 + 前两个列头」，例如「10-07 14:30 交易时间 金额」；用户可修改，明确保存才落盘，取消不新增记录。
- 保存成功后显示「映射已保存」，刷新已保存映射列表；当前文件列头匹配的新记录可见。失败显示原因，不显示成功反馈，也不清除本次字段选择。
- 列表只列匹配率至少 60% 的保存映射，标出缺失列名；分母是保存时全部规范化列头及出现次数，分子按相同列头及可匹配次数计算，不合并同义词。新增列不降低匹配率。
- 同义词在字段识别阶段可视为等价，但映射指纹阶段不合并；按既定规范化后的列头逐字匹配并保留出现次数，不把不同同义列头视为同一指纹。
- 每项提供 × 删除，不二次确认；删除后列表收缩，不自动选中其他项。删除已套用项不撤回本次已经呈现的字段绑定。
- 上限 20 份；满额只拒绝新增，同指纹可在明确确认覆盖后保存。存在同名列歧义的映射拒绝保存，但不妨碍本次修正和预览核对。
- 套用只复用字段绑定，不复用历史处理结论；缺失列留空，缺失必需字段须手动指定；新增列不自动分配角色。套用后执行字段修正同样的重算及决定重置。

## 七、三个关键流程

### 字段修正重算

- 字段下拉修改或套用映射后触发重算，立即显示「正在重算」，禁用确认导入及旧结果的处理操作；保留上一次有效预览的完整旧快照，仅供只读回看，不作为新映射的结果。
- 重算期间旧决定统一标记「已作废（映射已变，决定不能应用）」，不显示为新映射的已处理；旧快照中的单行、整组、退款对决定及未确认选择均不可修改、清除或应用，包括已转入将导入／规则跳过及被筛选隐藏的记录。
- 重新清洗取值、校验日期金额及方向，重新执行账目规则、重复核对与分类；新映射下无任何有效决定。旧快照的计数、进度及决定仅属于历史回看，不能当作当前计数、已处理量或提交依据。
- 重算成功后全部替换为新字段映射、互斥计数、明细和重新统计的进度；新结果无任何单行、整组、退款对决定或待生效选择，仍需人工确认的记录保持未决定。旧快照直接丢弃，不恢复、不合并旧决定。
- 重算失败后显示原因并保持提交禁用；旧快照及「已作废」标记保持，只读可回看，新映射下仍无决定。用户可修正映射重试或取消；重试期间保留同一旧快照，成功后直接丢弃，不将失败结果替换成旧的有效预览。
- 「已作废」使用明确文字与灰色／弱化样式，不能沿用绿色勾标或将「已确认」当作当前有效状态；允许查看旧原值和旧处理内容，但不提供恢复或应用旧决定的入口。首次读取尚无有效快照时，失败仅显示原因，不伪造历史记录。
- 字段映射修改重算后保持用户当前视图，不重新执行初次展示的默认视图规则；即使当前视图变为空，也留在该视图显示空结果。
- 保留搜索文本及仅看未处理的选择并在新结果上重新应用；连续修改以最后一次映射结果为准，过期结果不得覆盖当前预览、恢复决定或移除已作废标记；整个流程不写账本。

### 待确认处理

- 点击待确认卡片进入分组处理，使用原值、具体原因和最终入账预览进行核对；普通组选择动作后再确认，逐笔按钮直接明确决定，退款对按对确认。
- 明确决定后同步更新行结果、四类计数、已处理／剩余量及底部笔数；已确认可修改，清除本组决定恢复相关记录的待确认状态。
- 仅看未处理时隐藏已处理记录；取消该筛选可回看并修改，不因其最终归类到另一个卡片而失去处理历史。
- 所有待确认解决且必要字段有效时，提交入口才可用；入账按钮及组级动作均不得绕过金额和方向阻断。

### 长列表滚动

- 明细区内部滚动，搜索、进度、视图入口与底部操作保持可访问；待确认记录全部可达，不分页，不以 5 笔摘要截断。
- 超过 50 笔待确认时展示整轮进度；使用仅看未处理和定位下一笔辅助连续处理。处理后按当前筛选定位下一笔，不把已处理记录统一移到底部。
- 规则跳过／非交易行通过前 5 笔摘要及查看全部核对；搜索可直接命中第 5 笔以后的记录；无命中只代表当前筛选为空，不能宣称整批无待处理。
- 虚拟滚动本次不定，不能作为减少可访问记录或改为分页的理由；本文件规定交互验收，不承诺尚未测量的性能数字。

## 八、阶段 4 UI 验收要点

- 下拉只有一个实心三角，展开／收起方向一致；选项无灰色原生菜单，键盘选择、外部点击关闭、父窗关闭清理可用，禁用状态不能操作。
- 首次使用能沿顶部提示核对字段、找到待确认入口；知道当前处理哪笔、批量操作覆盖多少笔、选择是否已生效、提交为何禁用。小窗口下可滚动浏览记录，确认按钮不被挤出。
- 默认退款对自动展示两笔核对内容但不决定；多对分别核对后明确确认。单笔最终内容与原始值有明确分区，搜索／切换不残留其他视图的核对内容。
- 四张卡片均有展开入口；切换到正确视图及固定排序，搜索／切换不清决定、不重读文件，零结果视图不误改卡片数字。
- 映射只见最终列与待改高亮，所有列可修正，同名列有位置；必需字段缺失禁用提交，可选不使用，未暴露评分、置信度或算法候选。
- 普通组从未选择到已选择未确认，再到已确认，控件样式与数字更新严格符合三态；规则冲突组也须确认生效，不能以即时生效按钮替代。
- 已处理记录有勾标和真实结果，原位可回看；仅看未处理时隐藏，取消筛选后可改入账／跳过；清除本组涵盖已处理和隐藏记录。
- 退款预览含最终日期、正金额与正确备注顺序；零值、超过两位小数及方向未解决禁止入账；未知状态和真实未对账的支付成功不能自动当作成功。
- 退款对控件在标题行，默认组合不生效，多对各有明确范围；一对处理减少两笔待确认，按组合分类，歧义不强配对，清除组决定覆盖对内两笔。
- 94／86／8 的人工处理定义与例中 116 笔核对一致；逐笔／整组／按对确认、修改、清除均即时同步计数，不因搜索重复统计。
- 搜索分别命中行号、日期、带符号金额、备注及结果，能命中第 5 笔以后；纯空白和清空撤销文本过滤，无结果保持全局笔数与提交守卫。
- 保存可改默认名，有成功／失败反馈；60% 门槛、缺列、同名歧义、20 份上限、同指纹覆盖及 × 删除行为符合定稿；套用不恢复旧决定。
- 连续字段修改只保留最新结果，重算时提交禁用，全部相关决定被清除；500 笔待确认全部可访问、不分页，进度及定位可用，底部操作不被内容挤出。
- 取消／关闭不写账本，搜索不缩小最终提交集合；本次文档定稿不代表上述界面已经实现或验收通过。
